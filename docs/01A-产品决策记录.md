## 1. 已经确认（不用重复讨论）

| 项目 | 已确认结果 |
| --- | --- |
| 项目目标 | 在课程 RAG 基础上二次开发有业务差异的 AI 全栈产品 |
| 核心模式 | 普通 RAG 问答 + RAG 驱动的动态交互式诊断 |
| 诊断方式 | LLM 结合检索资料动态提问、生成选项和建议 |
| 人工规则 | 不建设手写故障诊断树或规则编辑器 |
| 其他功能 | 用户历史、管理员资料上传/知识库管理 |
| 实机范围 | 无真实 3D 打印机，不进行设备操作或真实维修测试 |
| 开发原则 | 复用现有 RAG；尽量最小改造，控制 AI Coding 时间与复杂度 |

D-01 ～ D-06 均已确认。PRD 作为当前需求基线；下一步评审《02-技术架构与改造方案》，随后再编写 AGENTS.md 和阶段任务。

## 4. 约束与风险提醒

- D-02 的免注册历史只适合本地和演示场景；若将用户端公开给多人使用，仍需评估会话隔离、访问控制和清理策略。管理员上传接口不能裸露在公网上。
- **已确认 D-01**：用户首页提供两个明确入口，普通问答与智能诊断的状态、输出形式不同；V1 不增加自动意图判断与模式切换逻辑。
- **已确认 D-03**：保留普通问答 MCP/Web 搜索能力并标记网页来源；诊断模式不调用联网搜索，不把网页结果混入诊断依据。
- **已确认 D-04**：V1 只支持 Creality K1；不为首版扩展多型号数据，但接口和数据归属不应硬编码为不可扩展。
- **已确认 D-05**：最多 3 轮澄清（不含初始描述与最终建议）；每轮生成 1～3 个互不依赖的问题，用户一次提交；不能为增加问题数量而编造资料依据。达到上限时不继续追问，输出有依据的建议或资料不足说明。
- D-06 已确认 React + Vite + Tailwind CSS + shadcn/ui。数据库细节、具体 LangGraph 节点和接口设计详见《02-技术架构与改造方案》，不得将静态方案当作已实现事实。
