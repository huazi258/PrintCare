## 4. 环境与运行复现

### 已观察到的本地材料

- 本机工作区有 `knowledge/.venv`，其 Python 为 3.10.8；`frontend/package.json` 要求 Node `>=22`，本机为 Node 22.11.0、npm 11.17.0。前端有 `package-lock.json`，并定义 `dev`、`build`、`lint`、`test` 脚本。
- 后端依赖入口是 `knowledge/requirements.txt`；代码实际还依赖 FastAPI/Uvicorn、`python-dotenv` 和上传表单所需的 multipart 支持，但这些没有在该 requirements 文件中明确列为顶层依赖。多数 Python 包也未锁定版本。
- `frontend/.env.example` 只给出两个 Vite 代理目标；`knowledge/.env.example` 只给出 `PRINTCARE_ADMIN_API_KEY`。代码还要求/读取 LLM、模型路径、Milvus、MongoDB、MinIO、Collection、MCP 等变量，见 `utils/client/ai_clients.py`、`utils/client/storage_clients.py`、两个 `processor/*/config.py`。
- 当前仓库没有已跟踪的 README、Compose/Dockerfile、数据库/Collection 初始化脚本或统一启动脚本。T3 验收报告给出过查询 8001、导入 8000、Vite 5174 的本机命令，但它不是可从零复现的操作手册。

### 复现判断与缺口

现有材料足以让已有本机环境继续运行：本地 `.venv`、`node_modules`、`.env`、模型路径和现有 K1 Collection 都存在时，可参考 T3 报告启动两个 FastAPI 服务和 Vite。它**不足以让另一位开发者从干净机器可靠复现**，主要缺口为：

1. 没有公开、完整且无密钥的后端环境变量模板，也没有变量用途、示例值格式、模型下载/本地路径说明。
2. 没有 MongoDB、Milvus、MinIO 的部署/连接/健康检查、Collection Schema/索引和 K1 数据导入说明；也没有 Compose 或等价基础设施脚本。
3. Python 依赖未完整声明或锁定，GPU/CUDA、MinerU、BGE-M3/Reranker 的平台要求和版本组合未固化。
4. 没有正式启动、停止、端口、代理、管理员密钥注入与安全边界说明；生产构建后的前端反向代理/静态托管方式也未定义。
5. 可再分发的 K1 演示资料、固定测试输入及其预期输出尚未形成可独立执行的测试集。`knowledge/test/fixtures/t3-03-04b-k1-import-verification.md` 是受控验证资料，但不是完整运行种子或授权说明。
