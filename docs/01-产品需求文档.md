# PrintCare AI 产品需求文档（PRD）

> 文档版本：V0.3（D-06 技术选型已确认，产品范围不变）  
> 状态：D-01 ～ D-06 均已确认；技术实现细节参见《02-技术架构与改造方案》  
> 目标阶段：可演示、可测试的 AI 全栈产品 V1  
> 原项目：基于“掌柜智库”课程项目进行二次开发；已有功能与新增目标须在 README 和项目汇报中明确区分。  
> 本文描述**计划交付的产品行为**，不表示相应功能已经开发完成。

## 1. 产品概述

### 1.1 定位

PrintCare AI 面向桌面级 3D 打印机用户，提供基于设备技术文档的智能知识问答和动态交互式故障诊断。V1 仅支持 **Creality K1**（保留未来多型号扩展能力），管理员上传经核对的设备资料，用户选择设备后即可查询知识或描述故障，并查看有来源依据的回答和诊断建议。

产品不是设备控制软件、通用闲聊机器人，也不是人工维修人员的替代品。没有真实 3D 打印机接入；验收基于资料与软件测试用例，不宣称真实维修有效性。

### 1.2 目标

- 将已有完整 RAG 系统转变为有明确业务目标、用户端和管理端的 AI 全栈产品。
- 保留原项目文档解析、向量化、多路召回、融合、重排序和流式输出等能力。
- 让用户通过**普通 RAG 问答**查找设备知识；通过**动态诊断**逐步澄清故障，而不是只阅读长篇回答。
- 对关键回答提供可验证的资料来源；诊断过程可保存、回看并恢复。
- 使产品可供 GitHub 展示与面试演示，并对原课程代码来源进行清晰说明。

### 1.3 本期非目标

- 不接入真实设备，不读取传感器，不发送硬件控制命令，不做真实维修验证。
- 不开发人工预设故障树、故障规则编辑器、多 Agent 系统或独立训练模型。
- 不做售后工单、支付、商城、社区论坛、设备远程监控、复杂权限与组织管理。
- 不要求根据用户上传的缺陷照片诊断（可留作未来扩展）。
- 不承诺覆盖全部品牌、型号、故障类型；没有资料的故障要明确告知。

## 2. 用户、角色与权限

| 角色 | 场景 | 可执行操作 |
| --- | --- | --- |
| 普通用户 | 查询 K1 设备资料和解决打印问题 | 选择设备、知识问答、发起/继续诊断、查看与删除自己在当前浏览器关联的历史、反馈结果 |
| 管理员 | 准备知识库 | 选择设备、上传 PDF/Markdown、查看导入结果与基础文档列表 |

**已确认（D-02）**：V1 普通用户免注册/登录，通过当前浏览器保存的匿名标识关联服务端历史记录；重新打开同一浏览器可读取记录与未完成诊断，但不支持跨浏览器或跨设备同步，清除浏览器数据可能导致记录无法找回。此方式仅面向本地/受控演示，不构成生产级身份认证或数据隔离；公开部署前必须补足会话访问保护，并限制管理员上传权限。

| 页面/区域 | 目的 | 主要内容 |
| --- | --- | --- |
| 用户首页/设备工作台 | 用户明确当前设备与任务 | 当前设备 K1、普通问答入口、智能诊断入口、最近历史 |

## 4. 功能需求（V1 范围）

### FR-01 设备选择与范围约束（P0）

- 用户在查询或诊断前能识别当前设备型号，首批为 Creality K1。
- 查询和诊断只能使用与已确认设备型号对应的本地知识切片；无法确认设备时提示用户选择，不能静默跨型号检索。
- 管理员上传资料时显式指定设备型号；不以 LLM 猜测的商品名作为唯一可信的设备归属。
- **已确认（D-04）**：V1 只支持 Creality K1；数据结构和业务接口应保留未来扩展多型号的可能，但不需要在 V1 引入多型号管理或切换数据。

**验收**：选择 K1 后检索仅返回 K1 关联的本地知识；缺失/歧义型号时有明确提示。

### FR-02 普通 RAG 知识问答（P0）

- 用户针对当前设备提出自然语言问题，支持连续多轮提问。
- 保留原 RAG 文档检索、融合、重排序和流式回答能力。
- 回答显示检索依据：至少包含资料标题与对应片段/章节标识；有可用原文链接时可打开。页码或精确定位仅在原始数据支持时提供，不伪造。
- 无相关资料、调用失败或超时时给出明确反馈，不以凭空推测代替检索结论。
- 普通问答保留现有 MCP 联网检索能力，联网资料与本地知识应显著区分并标注来源。

**验收**：能完成提问→检索→流式回答→查看来源；连续问题可合理使用会话上下文；无资料时有正确退路。

### FR-03 RAG 驱动的动态交互式诊断（P0）

**输入**：已确认设备型号，以及故障码或用户对打印异常的自由描述。故障码和自然描述统一进入诊断模式，不建设两套独立系统。

**基本行为**：
1. 保存原始故障描述与设备型号，检索相关资料。
2. 综合已确认事实、历史选择和资料，判断当前是需要补充信息、可以提供排查建议，还是证据不足。
3. 若需要补充信息，LLM 每轮根据本地检索资料动态生成 **1～3 个关键问题**（通常 2 个，按需减少），每题提供 **2～4 个易理解的选项**；可提供“不确定/其他”入口并允许补充文字。**同一轮的问题应可独立回答**，依赖前一题答案的问题须留到下一轮。
4. 用户可在同一页面批量填写本轮多个问题，统一提交；无法判断时可以选“不确定”。系统将整轮回答一次性保存，整合完整故障上下文重新检索或评估，再决定是否进入下一轮；不能直接将单条“选项文本”当成完整检索问题。
5. 当资料足以给出建议时，提供可执行但安全的排查步骤和资料依据；资料不足时明确说明不确定性并结束或提示补充信息。
6. 用户可主动结束诊断；给出建议后请用户标记“已解决 / 未解决 / 暂未验证”。AI 不能自行宣称真实故障已解决。

**明确约束**：
- 不人工编写故障分类决策树或预设故障分支。
- 模型输出为经过服务端校验的结构化数据；至少区分 `ask`（继续询问）、`answer`（提供有依据的建议）、`insufficient`（资料不足）。
- **已确认（D-05）**：单次诊断**最多 3 轮澄清追问**，每轮可以有 1～3 个相互独立的问题；不强制问满 3 轮，也不强制每轮问满 3 题。轮次不包括初始故障描述和最后的诊断建议。达到上限后必须输出有依据的建议或明确说明资料不足，不能继续追问。
- **已确认（D-03）**：动态诊断仅使用管理员已导入、且属于当前设备型号的可信本地知识库；诊断模式不调用 MCP/Web 联网搜索，也不得混入网页检索结果。诊断问题与建议必须能够对应本轮实际检索资料；资料不足时明确说明，不凭空推断。
- 涉及热端高温、电气、拆机等危险操作时，不得生成超出可信资料的自主操作步骤；不确定时建议停止尝试并联系官方支持。

**验收**：支持最多 3 轮“生成本轮问题组→用户一次提交多题答案→状态更新”；能根据资料动态选择 1～3 题，支持“不确定”，不重复已有事实；达到 3 轮时必须输出有来源的建议或信息不足状态；模型输出无效时可以安全回退。

### FR-04 诊断状态、反馈与恢复（P0）

- 每次诊断有独立记录 ID、设备型号、原始问题、当前状态、已确认事实、已提问/回答记录、追问轮次及结果。
- 状态至少分为 `in_progress`、`pending_verification`、`resolved`、`unresolved`、`insufficient`、`ended`（具体枚举由技术设计确认）。
- 同一用户刷新页面后，能重新进入未结束的诊断，看到此前的问题和选择并继续。
- 重复点击提交不应推进两次；处理期间提示等待。
- 用户反馈“未解决”时，若还未达到追问上限且有可靠资料，可在原诊断中继续；已经达到 3 轮上限时结束本次追问，允许回看或另起诊断，不能无限延长原会话。不得把“AI 已给建议”自动等同于 `resolved`。

**验收**：用户完成至少 2 轮选择后刷新页面，仍能恢复设备、事实和诊断进度；重复提交不会产生两条相同诊断轮次。

### FR-05 历史查询（P0）

- 用户可查看当前浏览器关联的问答和诊断记录，按时间倒序排列记录入口。
- 每条记录可进入详情；诊断详情包含问题、选择、建议、资料来源、用户反馈与当前状态。
- 未完成诊断可继续；支持用户主动删除自己的记录或清空历史（需要二次确认）。
- 不要求跨设备同步、搜索过滤、用户账户体系或复杂分析报表。

**验收**：退出页面、刷新后历史仍可查；删除后用户端不再显示被删除记录。

### FR-06 管理端文档导入与基础管理（P0）

- 管理员选择设备后上传 PDF 或 Markdown，沿用原有文档解析、图片提取、切分、向量化和 Milvus 导入能力。
- 展示文件名、设备归属、提交时间、处理中/成功/失败状态，以及导入节点进度或错误信息。
- 能查看已导入文档的基础列表，避免用户不知道知识库收录了哪些资料。
- 对同一设备上传重复文件应给出提示，避免无意识反复入库；具体去重策略在技术方案中确定。
- V1 不要求完整文档版本比较、分段人工编辑、批量迁移和复杂审核发布流。

**验收**：上传有效文档后，能够在管理端看到处理结果，并在用户端查到相关知识；无效格式/失败任务有清楚提示。

### FR-07 流式交互与异常体验（P0）

- 普通问答继续使用流式回答，诊断模式支持实时展示处理阶段和结构化问题/选项。
- 在后端生成中，前端显示明确的等待状态，禁止重复提交。
- 用户应能分辨：正在检索、正在分析、等待用户回答、已给出建议、处理失败。
- 网络断线或模型超时时，显示可重试状态；不得把失败任务显示成成功。
- 诊断问题的选项必须来源于服务端结构化响应，不让前端从自然语言文本中猜测选项。

**验收**：流式问答不回归；诊断卡片可正确展示、选择并继续；异常状态有可理解反馈。

## 5. 典型业务流程

### 5.1 普通问答

1. 用户进入工作台，确认设备为 K1。
2. 选择“知识问答”，提出问题，例如“如何完成首层校准？”。
3. 系统检索 K1 资料，流式展示回答并列出可核对的来源。
4. 用户继续追问或在历史中重新打开会话。

### 5.2 动态诊断

1. 用户进入“智能诊断”，选择 K1，输入故障码或描述（例：“首层总是粘不住打印平台”）。
2. 系统检索资料，依据证据和当前上下文判断要不要先询问。
3. 假设返回 `ask`：显示“问题 + 2～4 个选项”；用户选择“首层打印时”或输入补充说明。
4. 系统保存选择，组合原始描述与新增事实，再次检索和诊断决策。
5. 循环至输出 `answer` 或 `insufficient`；展示来源与局限性。
6. 用户反馈“已解决 / 未解决 / 暂未验证”，保存诊断记录；未结束的诊断支持刷新恢复。

> 上述示例问题和选项仅为交互演示，不能视为针对特定故障码或设备的有效维修规则。

### 5.3 管理端

1. 管理员进入受保护的知识库管理区，选择 K1。
2. 上传有权使用的 PDF/Markdown 技术文档。
3. 系统处理并展示进度；失败可查看原因。
4. 文档成功导入后出现在列表中，并可通过用户端知识问答与诊断检索。

## 6. UI/UX 原则

- 首页以“选设备—选任务”为主，不把所有操作藏在聊天框中。
- **问答页**保留熟悉的聊天结构；**诊断页**以分步骤问题卡片、进度状态、资料依据和结果反馈为主，支持流式过程提示。
- 一个屏幕内尽量只有一个主要操作；诊断选项应清晰、易点选，可选择“不确定”。
- 所有引用来源在视觉上明显区别于 AI 生成内容；缺少依据时明确说明。
- 适配电脑浏览器并兼顾移动端基本浏览；具体组件、视觉系统在 UI 设计阶段决定。
- 不用“AI 已修复/已解决”一类容易误导的表述，改为“给出排查建议”“用户确认已解决”。

## 7. 质量、数据和安全要求

- **质量**：保留原问答功能；新诊断不影响原 RAG 导入与检索链。对常见问题构建固定测试样本，验证设备范围、追问合理性、引用匹配及不确定性处理。
- **可恢复性**：诊断状态持久化在服务端，不能仅依赖内存 SSE 队列；刷新后可恢复；服务重启后已保存状态仍可读取。
- **引用**：至少保留资料标题、章节/片段标识和来源类型；不伪造 PDF 页码；不允许把不属于该型号的文档当作诊断依据。
- **可用性**：展示处理中的阶段状态及明确失败信息；长时间任务有超时与重试边界；不规定未经测量的性能数字。
- **安全**：管理员上传权限不得公开；对文件格式/大小进行服务端限制；不提交 API 密钥、隐私数据或未授权文档到公开仓库。
- **验证范围**：由于没有实体 3D 打印机，验收只覆盖软件流程、测试文档以及官方示例问题匹配，不承诺实机维修成功率。

## 8. P0 与延后范围

**本期 P0（必须完成）**：设备选择与隔离、普通 RAG 问答、动态交互式诊断、诊断状态持久化、历史记录、基础知识库上传/状态/文档列表、可靠引用、异常反馈、基本产品 UI。

**后续 P1（不进入 V1 验收）**：多个型号正式支持、资料版本管理及重索引、完善管理权限、诊断测试集与性能分析增强、更多来源的深度链接。

**明确不排期**：打印缺陷图片诊断、真实设备控制、售后工单、复杂注册与组织权限、多 Agent。

## 9. V1 验收场景（摘要）

| ID | 场景 | 预期 |
| --- | --- | --- |
| AC-01 | 导入一份 K1 技术资料 | 管理端可见成功状态，用户端可检索 |

| AC-06 | 诊断：最多 3 轮、每轮可一次回答多个问题 | 问题独立且有依据；整轮提交后状态正确累积；达到上限时不再追问 |
| AC-07 | 诊断过程中刷新 | 能恢复设备、问题、答案和当前状态 |
| AC-08 | 模型返回结构不合法 | 服务端拒绝坏数据，并提供安全重试/退路 |
| AC-09 | 资料不足或高风险操作 | 输出局限性/停止建议，不生成无依据操作 |
| AC-10 | 重复点击提交/网络中断 | 不重复推进诊断，不误报成功 |
| AC-11 | 用户反馈未解决/待验证 | 历史状态正确，未标记为已解决 |
| AC-12 | 回归普通问答及文档上传 | 原有业务链仍可运行 |
| AC-13 | 普通问答可联网，诊断不可联网 | 普通问答保留 MCP 能力，诊断全程不触发 Web 搜索或引用网络检索内容 |

## 10. 产品决策状态

已确认：

- **D-01**：首页采用方案 A，明确提供“知识问答 / 智能诊断”两个独立入口，用户自行选择模式。
- **D-02**：普通用户免注册，历史关联当前浏览器；管理员在对外部署前必须鉴权。
- **D-03**：动态诊断只检索已导入的可信设备资料，不执行联网搜索；普通 RAG 问答保留 MCP 联网检索。
- **D-04**：V1 仅支持 Creality K1，技术结构保留后续多型号扩展能力。
- **D-05**：单次诊断最多 3 轮澄清，每轮可动态生成 1～3 个独立问题，支持一并回答；信息足够可提前结束。

- **D-06**：前端采用 React + Vite + Tailwind CSS + shadcn/ui；TypeScript、前端目录和路由设计详见技术方案。
