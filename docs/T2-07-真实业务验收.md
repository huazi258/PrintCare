## 5. 多轮、反馈与恢复

诊断详情、同请求幂等、访客隔离和 SSE 断线后的详情恢复均以真实 MongoDB 和 HTTP 验证通过。

修复后，首层诊断真实返回了 3 道 `ask` 问题；用同一 HTTP 请求批量提交 `q1/q2/q3` 的回答（已清洁、未使用固体胶、打印超过 300 小时或更换过部件），MongoDB 正确保存全部答案。真实 LLM 的后续 `answer` 经校验后把会话从 revision 1 依次推进为“答案保存后的 revision 2”和“结果保存后的 revision 3”，状态为 `pending_verification`。随后：

- 对第一个独立会话提交 `resolved` 反馈，HTTP 和详情读取均为 `resolved`、revision 4，保留同一结构化 `answer`。
- 对第二个独立会话，在第 2 轮获得真实 `answer` 后提交 `unresolved`，状态变为 `unresolved`、revision 6；由于仍未达到三轮上限，使用 HTTP `resume_unresolved=true` 合法恢复执行。恢复后的真实模型结果为安全的 `insufficient`（revision 8），而非伪造新建议。
- 对已完成 resolved 会话使用相同的创建 `request_id` 重试，直接返回同一诊断 ID、revision 4 和 `idempotent=true`，没有再次执行推理。

## 6. 缺陷与修复

### 已修复：Reranker 的 Windows 控制台编码中断

真实首层检索首次暴露 Reranker 会把完整文档直接 `print()` 到 GBK 控制台。K1 手册含无法编码字符时，`print()` 抛出编码异常，Rerank 捕获后退化为所有文档无分数。

本轮移除了这些调试 `print()`，保持排序算法不变，并新增覆盖无法由 ASCII stdout 编码的手册字符的测试。修复后，真实 Reranker 可完成评分和断崖截断。

### 已修复：真实模型的引用格式重试与 Unicode 兼容

受控本地追踪只记录了候选的 action、来源 ID、短 excerpt 和 support_text，未保存完整 Prompt 或模型原文。首次候选是 `ask`：

- `chunk:469646834127762832` 的 excerpt 是 K1 手册“用干布对打印机做机身清洁，拭去灰尘和粘结的打印材料…”，但 `support_text` 选成“拭去灰尘和粘结的打印材料”，问题却是“是否已经清洁打印平台”；服务端因此正确返回 `unsupported_content`。
- 重试候选把手册中的 CJK 兼容字形改成了常规 Unicode 字符，原始逐字比较会产生 `invalid_excerpt`。这与历史 HTTP 中观察到的 `invalid_support` 同属“模型改写/字符兼容”问题，而不是伪造 source_id 或检索丢失。

修复措施是：Prompt 明确要求逐字复制、每题只保留一个可核验引用并给出短示例；决策节点在 `invalid_support`、`invalid_excerpt`、`unsupported_content` 时最多携带前一版候选进行一次完整 JSON 重试；输入给模型的手册正文和服务端回溯均使用受限的 Unicode NFKC 兼容归一化。没有接受伪造来源、删除 evidence 或放松 `answer` 的逐条建议/高风险校验。

对于 `ask`，校验改为“source_id、excerpt、support_text 仍须可逐字（或 Unicode 兼容等价）回溯，且问题须与 excerpt 共享非通用文本片段”。问题可以问用户是否执行资料描述的条件，不再要求 support_text 本身逐字出现在问题中；`answer` 的 conclusion/recommendation 仍维持 support_text 必须出现在对应文本的严格规则。无关但真实的 K1 excerpt 已由新增负面测试拒绝。

### 已修复：真实最终结论的逐字支持与追问改写

对首层粘附的受控复现显示，失败并非检索、历史事实丢失或来源伪造：模型首版确实返回了 `answer`，但把“建议在平台表面均匀涂抹固体胶”改写为“未涂抹固体胶”，又将涂胶与校准合并为一条建议。该支持短语没有逐字出现在对应 conclusion/recommendation，因此服务端以 `unsupported_content` 正确拒绝；有限重试仍沿用了同一改写。

最小修复只调整诊断 Prompt 和已有的 `unsupported_content` 修复提示：结论必须是资料直接支持的保守说明，每条建议只能对应一个逐字支持的操作，不能合并或重写。另一个真实复现发现“是否已根据提示在平台表面均匀涂抹固体胶？”会重复已回答的“是否已在平台表面均匀涂抹固体胶？”。决策节点现在只去除固定的是/否问句外壳（如“是否”“根据提示”“按照建议”）后进行重复比较；这不是语义模型或故障树。新增 Mock 用例覆盖 answer 的修复提示和这类问句外壳改写。

### 已修复：QA 流式任务状态回读

`answer_output` 现在在流式聚合完成后也写入任务结果。不会新增历史写入；SSE 仍发送原有 delta/final，`/status/{task_id}` 可恢复相同答案。
