# T4-02-02B 基础设施复现盘点

盘点日期：2026-10-13。范围仅限仓库、当前 Windows 主机可见的 Docker 上下文和代码；未启动、停止或修改任何容器、卷、数据库、Collection 或知识数据，也未读取本地 `.env`。

## 结论

现有“Linux 虚拟机 Compose 承载基础设施、Windows 主机运行服务与前端”的方案与代码连接方式相容，优先整理并复用该 Compose 是最低成本方向。但仓库未跟踪 Compose/Dockerfile，当前主机也没有可访问的虚拟机 Docker context，因此 Compose 的镜像版本、端口、网络、卷和依赖顺序均**尚未核验**；目前不能据此宣称可从零复现。

当前 Docker 上下文仅见本机 `default` 和 `desktop-linux`；尝试只读列出 Compose 项目/容器时，`desktop-linux` 的 Docker Desktop 命名管道不可连接。该结果只说明当前 Windows Docker Desktop 不可用，**不表示 Linux 虚拟机中的容器已停止或配置不存在**。

## 已知基础设施结构

| 组件 | 已确认依据 | 复现含义 | Compose 细节状态 |
| --- | --- | --- | --- |
| Milvus | 用户说明其在 Linux VM Compose 中运行；`knowledge/utils/client/storage_clients.py` 用 `MILVUS_URL` 创建 `MilvusClient` | Windows 查询/导入服务必须可访问其 HTTP/gRPC 暴露地址；账户/网络须允许 Collection 与索引操作 | 镜像、端口、网络、卷、依赖均未核验 |
| etcd | 用户说明其由同一 Compose 管理 | 是 Milvus 服务依赖，不能只单独复制 Milvus 容器 | 同上 |
| MinIO | 用户说明其在 VM Compose 中运行；同一客户端读取 `MINIO_*`，固定以 `secure=False` 连接 | Windows 导入服务需要可达的 `host:port`、凭据和 Bucket 权限 | 同上 |
| MongoDB | 用户说明其在 VM Compose 中运行；同一客户端读取 `MONGO_URL`、`MONGO_DB_NAME` | Windows 查询服务需要可达且可读写目标库 | 同上 |
| Attu | 用户说明其在 VM Compose 中运行 | 仅运维查看工具，不是后端运行时依赖 | 同上 |
| Windows 查询、导入与前端 | `knowledge/api/query_router.py`、`knowledge/api/import_router.py` 与 `frontend/vite.config.ts`；默认 8001、8000、5174 | 通过环境变量访问 VM，不需要把 FastAPI/React 移入 Compose | 已有运行命令见 `docs/T4-02-01-本地运行说明.md` |

前端开发代理默认把 `/api/core` 转发至 `127.0.0.1:8001`，把 `/api/admin` 转发至 `127.0.0.1:8000`；它不直接访问 VM 中的数据库。后端连接地址及凭据应只保留在 Windows 主机的忽略文件 `knowledge/.env`，不要放入 `VITE_*` 变量或提交到仓库。

## 容器启动、初始化与知识数据是三层不同工作

1. **容器启动。** Compose 需先使 Milvus（及 etcd）、MongoDB、MinIO 可从 Windows 主机到达。当前代码没有 Docker healthcheck、Compose 或外部依赖就绪探测脚本，不能由服务启动替代基础设施就绪检查。
2. **数据库/存储初始化。** MongoDB 没有仓库内 bootstrap 脚本：问答首次写入会使用 `chat_message`，诊断首次创建会使用 `diagnosis_session`；后者在 `knowledge/utils/diagnosis_session_util.py` 首次写入时创建三个索引（`diagnosis_id` 唯一、`visitor_id + updated_at`、以及部分唯一的 `visitor_id + creation_request_id`）。MinIO 客户端首次初始化会检查 `MINIO_BUCKET_NAME`，不存在时尝试创建 Bucket；原文件对象名为 `origin_file/<YYYYMMDD>/<filename>`（`knowledge/services/import_file_service.py`）。这些是应用的惰性行为，不是已独立验证的初始化程序。
3. **K1 业务知识数据。** 这是独立于容器和 Mongo/MinIO 初始化的步骤。导入 LangGraph 位于 `knowledge/processor/import_process/main_graph.py`；首次导入会在缺失时创建 `CHUNKS_COLLECTION` 与 `ITEM_NAME_COLLECTION`，然后写入向量和文档数据。没有可重复执行的种子数据或独立迁移脚本，不能通过删除/重建现有 Collection 来“初始化”。

K1 默认 Collection 名称为 `printcare_k1_chunks_v1` 和 `printcare_k1_item_names_v1`（`knowledge/.env.example`、`docs/04-T1环境配置说明.md`），必须继续与旧课程 Collection 隔离。Chunk Collection 由 `knowledge/processor/import_process/nodes/import_milvus.py` 按首批向量维度创建，含 `chunk_id` 主键、正文/标题/文件/`item_name` 字段和稠密、稀疏向量；启用动态字段，因此导入的 `device_id`、`device_model` 可以保留。索引为稠密 `AUTOINDEX/COSINE` 与稀疏 `SPARSE_INVERTED_INDEX/IP`。Item-name Collection 在 `nodes/item_name_recognition.py` 创建，稠密向量维度固定 1024，索引类型相同。

## 可复用性与缺失材料

现有 Compose 在以下材料完成脱敏复核后，适合原样整理为仓库的基础设施入口；目前不应新设计第二套部署方案。

| 所需最少材料 | 用途 | 当前状态 |
| --- | --- | --- |
| VM 上的 `compose.yaml`/`docker-compose.yml`，以及引用的 override 文件 | 核对服务、镜像标签、端口、网络、volume、`depends_on` 与 healthcheck | 仓库未找到，未获得 VM 文件 |
| Compose 环境变量的**模板**或 `docker compose config` 的脱敏输出 | 找出必填非密钥参数、固定 IP、主机专属路径和凭据引用 | 未获得；不得提供真实密钥 |
| VM 暴露给 Windows 的端口/网络说明 | 将 `MONGO_URL`、`MILVUS_URL`、`MINIO_ENDPOINT` 映射为可达地址，确认防火墙/仅主机网络边界 | 未获得 |
| 只读的容器状态与持久化目录/命名卷清单 | 确认现有数据实际落点及备份边界，不操作数据 | 未获得 |
| K1 导入资料来源、导入顺序与现存 Collection 约束 | 让新环境建立同一类受控知识数据，而非复制未知/无授权资料 | 仓库仅有验证资料与历史验收记录；无可再分发种子包 |

整理时需特别排除真实访问密钥、Mongo URI 密码、MinIO 账号、固定局域网 IP、用户目录/磁盘路径和已有数据卷内容。若 Compose 已绑定这些机器专属信息，应改为无密钥模板与本机忽略的环境文件，而不是把原文件直接提交。

## 最小复现建议（后续执行，不在本轮操作）

1. 取得上述 Compose 文件和脱敏变量清单，先做静态审查；确认其可在新 Linux VM 使用命名卷或明确的数据目录、没有固定 IP/私有路径/密钥后，再决定是否纳入仓库。
2. 保持基础设施在 Linux VM，Windows 仅在 `knowledge/.env` 配置指向 VM 的 Mongo、Milvus 与 MinIO 地址；用 `knowledge/.env.example` 作为无密钥对照。不要把数据库凭据传给前端。
3. 在获准的新环境中按“Compose 就绪 → 连接检查 → 由受控导入创建 K1 Collection → 导入有授权的 K1 资料”执行；分别记录每层结果。Mongo 索引与 MinIO Bucket 的惰性创建只能作为补充，不应被误写成完整 bootstrap。
4. 后续再补一个经实际验证的、无密钥的基础设施说明和初始化边界；在没有可再分发 K1 资料前，文档应把知识数据导入明确为人工前置条件。

## 本轮边界与未验证项

没有执行 Compose、容器、数据库或 Collection 操作；没有启动服务、运行测试或访问真实环境变量。因此所有具体镜像版本、容器端口、网络名称、卷名、启动依赖、现存数据量和 VM 可达性均为 **Not Verified**。T3 历史报告中记录的真实 K1 数据与服务联通只可证明当时环境曾可用，不能替代本轮对 VM Compose 的配置核验。
